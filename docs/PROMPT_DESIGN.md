# Prompt 设计：不变层、可变层与 AI 味防线

本文汇总 prompt 工程层面的三个关键设计。

## 不变层 vs 可变层

```
┌─────────────────────────────────────────────────┐
│ 不变层（训练产出）           │ 可变层（每次填入）    │
│ - prompt 结构（LLM 自设计）  │ - 题材/世界观        │
│ - 写作规则/约束              │ - 角色信息           │
│ - 输出格式要求               │ - 本次情节方向       │
│ - 自检清单                   │ - 场景节拍与锚点     │
└─────────────────────────────────────────────────┘
```

关键立场：**不变层的具体字段和结构由 LLM 在训练中自己决定，不是人预设的。** 人负责定义评分与闸门，结构搜索交给模型；但搜索的锚点（人类偏好集 + canary 对抗集）必须由人冻结。

## 固定 prompt（`config/fixed_prompts.json`）

本仓携带的唯一调优资产。包含各生成环节的固定 prompt 模块（骨架抽取、场景生成、审阅修正等）。模块化是为了让 PromptOpt 的 bounded edit 能对单个模块做可回滚的定点修改（`prompt_vXXXX.md` 版本化 checkpoint），而不是每次全量重写。

## AI 味防线要点

中文网文场景下，AI 腔有一组稳定的、可规则化的特征。`prompt_harness/ai_flavor.py`（1100+ 行）按三层设防：

1. **格式契约（硬性）**：中文弯引号等标点规范全系统强制，违反即打回；
2. **句式禁令（防御性写作）**：针对"不是……而是……"滥用、排比堆砌、升华说教、翻译腔、微动作慢镜头等具体模式的检测与改写指令；
3. **配比公式**：对白间隙公式控制对白/叙述密度，防"堆对白"和"流水账"两个相反方向的失败。

每条规则都对应一类真实生成事故的归纳，规则的增删由 canary 对抗集与多维评分驱动，而不是审美偏好。

## 与 PromptOpt 的关系

prompt 模块、评分器参数都是**可训练文档**：rollout 产出轨迹 → analyst 复盘错误/成功模式 → minibatch 定点 patch → bounded edit（保护区域不可动）→ validation gate（多维均不得降 + canary 否决）→ checkpoint。失败 edit 进入 rejection buffer，避免重复踩坑。
