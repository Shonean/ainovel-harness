# 架构：五层信息阶梯

本文说明系统的核心数据结构与生成链路。

## 为什么分层

长文本生成失败的主因不是"模型不够聪明"，而是**信息断层**：prompt 里同时塞着全书主线、卷级弧线、章纲、场景节拍，模型分不清哪些是硬约束、哪些是背景氛围，于是该遵守的事实被改写（乱编），该推进的情节被匀速稀释（流水账）。

AInovel Harness 的做法是把上下文显式拆成五层，每层有独立的职责、字数预算与注入位置：

| 层 | 内容 | 职责 |
|----|------|------|
| l1 | 全书骨架（logline、主线承诺、结局锚点） | 定调，防跑题 |
| l2 | 卷级弧线（本卷要完成什么） | 控制节奏走向 |
| l3 | 章纲与场景序列 | 章间衔接 |
| l4 | 场景级节拍（含**字面锚点**） | 硬事实约束——本层是生成质量的实际决定者 |
| l5 | 正文成稿 | 唯一输出层 |

## 双向阶梯

- **向下生成**：l1 → l5 逐层细化，每层产物经作者确认后下沉。
- **向上抽取**（X4→X3→X2→X1）：从已有正文反向抽取各层骨架。分析已有小说与生成新小说共用同一套表示，修改可以发生在任意一层。

## 字面锚点与反漂移

l4 节拍中的关键事实（人名、数字、物件、承诺）以**字面锚点**形式写进 prompt，生成后由 fact_recall 类检查验证其在成稿中原样出现。配合元素白名单与硬约束在阶梯特定层的注入，构成事实反漂移机制。

## AI 味防线（`prompt_harness/ai_flavor.py`）

生成后逐段审阅：

- 中文弯引号等**格式契约**全系统强制；
- 标点/句式硬约束与防御性写作禁令（"不是……而是……"滥用、排比堆砌、微动作慢镜头等）；
- 对白间隙公式控制对白/叙述配比。

这些规则来自上百万字生成实践的错误归纳，是领域级（中文网文）资产。

## PromptOpt：两层共演化优化

`prompt_harness/promptopt/` 实现了不动模型权重的训练循环（rollout → reflect → minibatch patch → bounded edit → validation gate → checkpoint），分两层：

- **Level 1（评分器）**：ScorerParams（权重/阈值/词表/LLM 审阅 prompt）被优化，锚点是冻结的人类偏好集（Kendall τ）与 canary 对抗集（防评分器被攻破后放水）。
- **Level 2（prompt）**：各 prompt 模块被优化，锚点是已验证的评分器，gate 要求 fact/plot/flavor 多维度均不得降。

设计动机：评分器是手搓的、会被 Goodhart——我们先抓到评分器 bug 让消融结论失真，又用 15 条 canary 对抗样例抓到它 9 处放水。**先让评分器可信，再用它优化 prompt**，是这个框架与"拿 LLM 打分直接搜 prompt"类工具的本质区别。

## 技术栈

- 后端：Python / FastAPI（`app/dashboard/app.py`，端口 8765），prompt-harness 经 lifespan 挂载
- 前端：React 19 + Vite 6（`app/dashboard/frontend/`）
- 存储：SQLite（统一数据库，WAL + 版本化迁移，自动快照）
- LLM：OpenAI 兼容端点（火山方舟预设），llm_client 统一封装
